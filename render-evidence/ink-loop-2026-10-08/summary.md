## 修复：位置 → 原因 → 修复 → 验证

1. **位置**：`src/combat/tidewater_combat.gd` 的 `_paint_roll_team()`，玩家与机器人共用的贴地滚涂路径。
2. **原因**：原落墨点沿世界 Y 轴抬高 0.35 m，并从角色高度向前伸出 0.75 m。上下坡时点到坡面的法向距离不同，导致下坡球形墨迹与坡面的相交范围明显收窄。十条潮水码头坡道均复现方向差异。
3. **修复**：先查询角色实际支撑面，沿该平面预测前方采样高度，再在本地步高范围查询真实支撑；沿实际表面法线保持 0.35 m 的落墨距离。查询包含铁网碰撞层，并拒绝不可涂或非行走支撑。没有更改墨耗、伤害、部位倍率、落后增益、道具冷却、天赋、复活选择或 CPU 计分算法。
4. **验证**：固定 RNG、相同接触中心与 11 次滚涂，比较两个方向、两队调用路径；补水面空缺、不可涂支撑和铁网负例，并覆盖其他六图代表坡道。

| 场景 | 修复前／中间负例：两个方向的着墨格数 | 最终结果 |
| --- | --- | --- |
| 潮水码头坡道 face 133 | 156 / 31 | 133 / 133 |
| 潮水码头对称坡道 face 270 | 30 / 153 | 133 / 133 |
| 潮水码头平地 face 76、119 | 138 / 134 | 138 / 134 |
| 珊瑚集市较陡坡道 face 50 | 第一版局部射线修复为 0 / 135 | 加入支撑平面预测后 134 / 135 |

潮水码头十条坡道、两处平地及七图代表坡道的方向差异均小于 5%，两队都通过。表中数值只比较固定路径的有效着墨格数，不代表整局平衡或所有坡道边缘的穷举验收。

## 无界面规则检查与夹具修正

`./tools/run_checks.sh` 最终结果为 **104 通过、0 失败**，包含 GDScript 编译门及 **270 个本地资产**的哈希、大小和清单完整性。没有改写资源清单、地图资产或已有资源 UID。

完整检查曾暴露旧 `check_tidewater_bot.gd` 的间歇失败。原夹具用 0.1 秒推进 AI，同时 `move_and_slide` 使用 1/30 秒物理步长，还要求最终中心射线命中与脚底同高的地面。已复现机器人脚底在平台 2.2 m 高处由胶囊边缘支撑，而中心射线落到下层 0 m 地面的误判。

夹具改用固定均衡天赋、RNG 和一致的 30 Hz 模拟物理时钟；对实际贴地样本检查支撑接触，缺少滑动接触时查询胶囊脚印范围。保留离开出生区、推进、碰撞净空、实际涂地及终场冻结检查，新增向上移 2 m 的悬空负例。未修改生产机器人移动或寻路策略。

修正后 12 个独立进程重复均通过；每次 720 个物理样本中 709 个贴地样本通过支撑检查，移动 123.07 m、沿地图推进 69.56 m。

证据：[最终统一检查](full-checks.txt)、[资产完整性](final-check_asset_integrity.txt)、[最终机器人专项](final-check_tidewater_bot.txt)、[12 次重复](bot-support-repeat.txt)、[原夹具 50 次重复与 4 次失败](bot-old-fixture-repeat.txt)、[支撑误判复现](bot-support-before.txt)。[中途失败的完整检查](full-checks-failed-bot-fixture.txt)保留为诊断记录，不算最终通过证据。

## 原生自然计时 180 秒滚筒 5v5

2026-10-09 单独运行 `measure_native_match.gd --map=tidewater --weapon=roller`，期间没有并行运行检查。首页 → 设置 → 开场 → 180 秒对局 → 2.6 秒终场 → 结算 → 首页全部完成；对局实际墙钟时间 181.42 秒，生产计时、机器人、生命、墨水与角色位置未由夹具改写。

1. 玩家为滚筒／墨水手雷／均衡天赋，10 个角色均进入对局和结算。
2. 7 次自然死亡、7 次完成复活。每次倒计时结束后等待 0.833 秒，由 Enter 对已选出生点显式确认；未发生静默自动选择或夹具强制死亡。
3. 玩家实际移动累计 678.81 m，自动输入包含滚涂、潜墨和跳跃。最终覆盖率为 26.402% / 16.582%，结算值与 CPU 归属一致。
4. 个人累计涂地 1040.78 m²、存活积分 1021.91 p；两队个人累计涂地之和分别为 3842.54 / 3329.13 m²，与整局团队累计账本一致。累计涂地、存活积分和最终覆盖率分别核对，不互相替代。

## 重现

在项目根目录执行统一检查：

```sh
./tools/run_checks.sh
```

受控原生检查必须指定一个尚不存在的绝对目录：

```sh
/Applications/Godot.app/Contents/MacOS/Godot --path . \
  --rendering-method forward_plus --rendering-driver metal \
  --script res://tools/capture/verify_tidewater_ink_loop.gd -- \
  --output=/private/tmp/tideink-ink-loop-new
```

自然整局使用新的证据目录，避免覆盖本批记录：

```sh
/Applications/Godot.app/Contents/MacOS/Godot --path . \
  --rendering-method forward_plus --rendering-driver metal \
  --script res://tools/measure/measure_native_match.gd -- \
  --output=res://render-evidence/ink-loop-new/match \
  --map=tidewater --weapon=roller
```

已知 macOS 无界面检查的系统 CA 查询诊断由统一入口精确过滤；本批原生日志只有系统输入法 mach port 诊断，没有脚本／解析／资源错误。
